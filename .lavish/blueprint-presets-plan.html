Blueprint presets in Nurgling Architect

The planner's output becomes the game's own Base planner presets: same files, same folder, both ways. Planned on 2026-10-13 against nurgling2 commit a14d18be6 Blueprint presets.

1. What the game does (read from the code)

ThingIn nurgling2
Folder%APPDATA%\Haven and Hearth\planner_presets\, one .json per preset, shared by every profile and world (PlannerPresetStore). You already have Layer_01.json there.
File{format:1, kind:"layer"|"folder", name, description?, size:{w,h} (tiles), layers:[{name, ghosts:[{res, sdt? (base64), x, y, angle}]}]}. x/y are world units from the box's top-left tile corner, so every object keeps its sub-tile snap.
SavingTwo ways: Save preset (the selected layer, or a folder with all its layers) and Save region (drag a rectangle: every visible layer's objects inside; a folder preset if more than one layer). Box size comes from the objects' footprints (NHitBox custom box, else one tile).
File namesSlug of the name (AreaPresetStore.slug), -2, -3… if taken. Written atomically (.tmp then rename, keeps a .bak).
PlacingStamp follows the cursor a whole tile at a time (cursor = middle of the box), wheel/R turns 90°, F mirrors, left click places, right click/Esc cancels. A layer preset becomes a new layer in the open folder; a folder preset becomes a new root folder.
WindowList with thumbnail, size, object count; Place, Rename, Delete, Export, Import, Edit description.
Object state (sdt)Only used to draw the ghost. It is whatever the server gave the placing ghost: your file has the fireplace as Aw== (parts 0+1) and the metal cauldron as AAg= (part 11), the same variant bits the planner already uses.

2. Design

2.1 Same folder, same format, no shared code

  • Read and write %APPDATA%\Haven and Hearth\planner_presets\ directly (the planner already knows that root for area presets). Created on first save if the game was never run.
  • Own small reader/writer for format 1 in the planner (architect.io.Blueprints), not nurgling's classes: the pinned engine jar predates them and the projects stay independent. A test reads your real game file and checks a round trip.
  • Lossless rewrite: rename/describe edits only name/description in the original JSON, so fields a newer game version adds survive. Files of another format are listed greyed ("made by a newer game") and never rewritten.
  • Same slug naming, same atomic write with .bak, delete removes the .bak too — so the game sees exactly what it would have written.

2.2 Saving from the planner

ActionMakesWhere in the UI
Save layer / folder as blueprintThe selected layer (kind:"layer") or a folder with its layers (kind:"folder"), like the game's Save presetLayers panel: new Save as blueprint button (acts on the active layer or its folder; folder rows get it too)

Name and optional description are asked in a small dialog. Objects are written as the planner draws them: the object's own state if it has one (cauldron/plow variants), else the planner's default look (all parts for tar kiln/stockpiles, grown crops) so the game shows them instead of an invisible ghost.

2.3 Loading (placing) in the planner

  • Blueprints window → Place: the same stamp as the game — ghost previews of every object, whole-tile moves, wheel/R turn, F mirror, left click places, right click/Esc cancels; the box turns red outside the plannable world.
  • Result matches the game: layer preset → new layer in the active folder; folder preset → new folder with its layers. Names made unique (Mill yard, Mill yard 2).
  • One undo step undoes the whole stamp, new layers and folder included.
  • Turn and mirror use the game's exact math (ported from PlannerPreset.transformed), checked by tests on the same inputs.
  • Objects the planner cannot draw are still placed (and saved back), just without a preview; the status bar counts them.

  • Toolbar gets a Blueprints button (lit while open), next to Areas/Terrain.
  • The list re-reads the folder when the window opens and every few seconds while open (cheap: compares file times), so presets saved in the game show up without restarting.

2.5 Small fixes that come with it

  • Fireplace build entry gets the game's state (pow parts 0+1) instead of "all parts", so planner and game show the same fireplace.
  • AreaPresets and Blueprints share one place for the game folder path.

3. Steps

  1. Format — architect.io.Blueprints: parse/write format 1, slug names, atomic write + .bak, lossless rename/describe, list/delete/import/export. Tests: your Layer_01.json round trip, unknown fields kept, other formats refused.
  2. Transform & capture — box from the objects' footprints with the tile-corner origin; turn/mirror ported 1:1. Tests: game math on fixed cases, capture → place reproduces the exact positions.
  3. Placing — BlueprintStamp tool in the view (previews, turn, mirror, red box, cancel), plan insertion as one undo step including new layers/folder.
  4. Saving — layer/folder, region drag, selection; name/description dialog; state written as drawn.
  5. Window — list, thumbnail, buttons, auto-refresh, toolbar button, status hints.
  6. Check against the game — save in the planner → open in nurgling2's Presets window and place; save in the game → place in the planner. Screenshots of both. (Needs you to run the game for the game side, or I run it with your OK.)
  7. Build, tests, commit, push.

4. Decisions for you

D1 — Box size. The game sizes the box from nurgling's hand-made hitboxes (one tile for anything without one, e.g. most buildings), so big buildings poke out of the box. I'd use the planner's exact footprints (the real collision shapes) for presets saved in the planner: the box then really contains everything, and the game places them the same way. Alternative: copy the game's rule exactly so the same layout saved in either app gives an identical file.
D2 — Writing into the game folder. Until now the planner never wrote into the game's files. This plan writes, renames and deletes in planner_presets\ only (nothing else of the game's), with a confirmation for delete. OK?
D3 — Areas. Game blueprint presets hold objects only; areas have their own presets (the planner already exports those). Keep them separate (my suggestion), or also offer "save areas too" writing an area preset with the same name?
D4 — Save selection. A planner-only extra (the game has region and layer/folder). Include it?

5. Risks

Objects only the planner has. The planner can place things the game never puts in a Base plan (trees, herbs, rocks, wall pieces). The game draws any of them as ghosts, but some may need state the game can't guess; they are written with the planner's look, which fixes most. Checked in step 6.
Game running at the same time. The game reads the folder when its window opens and writes whole files atomically; the planner does the same, so the worst case is a list that is a few seconds stale.
Format drift. If nurgling2 bumps the format, the planner lists those files greyed and leaves them alone until updated.
