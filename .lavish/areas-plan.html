Areas in Nurgling Architect, like the game's

Draw areas, name them, put them in folders, give them specialisations and Take/Put rules — then save them as area presets the game places as-is. Plan only, nothing built yet. Read against nurgling2 at a14d18be6.

So the data side is already right — areas made from stamped presets keep everything and export intact. What's missing is the editing, and a proper save to the game's preset folder.

How the game edits them (to copy)

  • Specialisations: a searchable list of every kind with its icon (nurgling.widgets.Specialisation), the bots that use it in the tooltip (SpecialisationUsage); some have a subtype menu (SpecialisationData: crop, seed, fuel per burner, barrel contents, cistern, cheese racks…) and crop fields a minimum harvest stage.
  • Take / Put: you drag an item from your inventory onto the box; a gear sets a threshold and the storage type. The planner has no inventory — this is the one thing that needs a new way in (§2.3).
  • Presets: %APPDATA%\Haven and Hearth\area_presets\, one JSON per preset, same naming/atomic-write rules as blueprints; built-ins ship inside the client jar (the planner already reads those).

  • Toolbar Areas opens it (replaces today's small panel). Left: areas grouped in the game's folders, drag an area onto a folder to move it, + Folder / Rename / Delete. Middle: the selected area. Right: Take and Put, as in the game.
  • On the map (Areas mode): drag on the ground draws a new area (tile-snapped), click selects (Shift adds), drag a selected area to move it, drag its edges or corners to resize, Del deletes, arrows nudge, Ctrl+C/V duplicate with all settings. Names drawn on the areas as now. Sides over 100 tiles are refused with a hint (the game would reject the preset).
  • Copy / paste settings: copy specialisations + Take/Put + fill from one area, paste onto one or many selected ones — fast for "ten identical cupboard areas".
  • Everything is one undo step per change, like objects.

2.2 Specialisations

  • The list, names, icons and subtype choices come from the game's own classes in the engine jar (Specialisation.SpecName + findSpecialisation, SpecialisationData, FuelZones, crop stages) — not copied — so the planner offers exactly what that client version knows; refreshing the engine (sync) brings new ones.
  • "+ Add specialisation" opens a searchable picker (icon, name, which bots use it). Subtype picked from a small menu; crop fields get the min-harvest-stage choice.
  • Saving writes the same {name, subtype, min_harvest_stage} objects the game writes.

2.3 Take / Put without an inventory

  • "+ Add" opens an item picker built on the client's own item vocabulary, nurgling.tools.VSpec (read from the engine, not copied): 1,078 items in 127 categories (Spices, Crop Seeds, Fish, Tuber…), each already in the exact Take/Put form {static, name} with the names the bots match. Browse by category or search; items used in the built-in area presets are added to it.
  • An entry is written exactly like the game's: {name, static: "gfx/invobjs/…", type, th?}.
  • Per item: threshold, storage type (Container / Pile / Barrel / Barter), remove — the game's gear menu.
  • Free-text fallback ("Other item…"): type the exact in-game name for anything the list lacks, optional icon. Bots match items by name, so this must be the name the game shows.

2.4 Area presets, both ways

  • Save as preset (game format 1, into the game's area_presets\ folder, same naming/.bak/lossless-rename rules as blueprints): selected areas and/or folders (folder paths kept relative, as the game's capture does) · all visible areas · a dragged region. Name + description prompt.
  • Presets…: built-in (from the engine) and yours, with description and a footprint thumbnail; Place (stamp: wheel/R turn, F mirror, click, Esc), Rename, Describe, Delete, Export, Import — the Blueprints window's pattern.
  • Stamping uses the game's exact turn/mirror, including turning the fill direction (missing today), and puts the areas in a folder named after the preset, like the game.
  • Today's "Export areas" file dialog goes away in favour of this.

2.5 Small things that come with it

  • Areas exist only to make presets: nothing is read from the areas players have in their game. A preset can still group its areas in sub-folders (the preset format's path, e.g. "Racks"); that is just a field on the area. Planner layers keep doing show/hide/lock.
  • Area labels show the main specialisation icon next to the name.
  • Status/hint line explains Areas-mode mouse and keys.

3. Steps

  1. Model: editing operations on areas (name, colour, path, hide, fill, specs, items) as undoable changes; preset entries round-trip losslessly. Tests: every built-in game preset → planner → saved → identical; game turn/mirror parity incl. fill.
  2. Map tools: select / multi-select, move, resize handles, duplicate, 100-tile limit.
  3. Areas window: folder tree with drag-to-folder, details column, Take/Put columns.
  4. Specialisation picker from the engine's lists, subtypes, crop stage.
  5. Item picker from VSpec categories + built-in preset items, search, free text; threshold/type menu.
  6. Presets: shared preset-folder code with Blueprints; save (selection/folders, visible, region), presets window, stamping with fill direction.
  7. Check against the game: a preset saved in the planner listed and placed by the game with specs and Take/Put intact (needs the game running — you, or me with your OK).
  8. Build, tests, commit, push.

5. Risks

Item names. A few items show a different name in-game than their resource's tooltip (meat cuts, some dynamic names). Free text and the built-in-preset names cover them; the picker shows the exact name that will be written.
Engine version. Specialisations follow the engine snapshot in the planner. A spec added to nurgling later appears after the engine is refreshed; unknown specs in an imported preset are kept and shown by name, never dropped.
Pending: engine slimming. The earlier "slim the engine + rewrite history" step is still waiting on your OK.
